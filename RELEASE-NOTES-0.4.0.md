## Ordinary callback and caller migration

Regenerate ordinary skeletons and migrate subclasses and caller send sites:

```java
public final short dispatchTo(byte ins, byte p1, byte p2,
        byte[] requestBuffer, short requestOffset, short requestLength,
        byte[] output, short outputOffset, short outputCapacity);

protected abstract short onEcho(short prefix,
        byte[] payload, short payloadOffset, short payloadLength,
        byte[] output, short outputOffset, short outputCapacity);
```

Byte-sequence and packed response callbacks write the existing encoded field
order into the caller-owned output span and return the produced length instead
of returning an array. Scalar callbacks retain byte/boolean/short/int returns;
void callbacks remain void. Each byte-sequence request argument becomes a
borrowed buffer/offset/length triple referencing the original request buffer.
Generated ordinary dispatch no longer allocates request slices or reply arrays.

Fully receive the command and capture INS/P1/P2 before overlapping writes.
Send only after successful `dispatchTo`, using exactly `outputOffset` and the
returned produced length; map `StatusWordException` in the caller. A refusal
returns no sendable length. No constructor APDU binding or retained incoming or
output reference is required or permitted by the ownership contract. Subclasses
must keep command buffers local and consume needed borrowed input before
overwriting it. One `packBytes` copy has memmove semantics; multiple copies
still require deliberate ordering or caller-owned workspace.

F1 naming reserves every request field, including later fields and occupied
suffixes, before allocating ordinary locals, span parameters and borrowed
companions. Generated parameter names may vary to avoid collisions. Callback
types/order and positional dispatch remain stable; no new IDL prefix restriction
or field rename is required. Noncolliding schemas preserve their generated bytes.

## Capacity, refusals and deployment bounds

Spans use nonnegative JavaCard shorts and arrays within the short-indexed model
(at most 32767 bytes). Empty end spans are allowed. Null output refuses; null
request is allowed only for offset/length `(0, 0)`. Window checks validate the
offset before subtracting from array length. Fixed requests require exact data
length, including zero for P1/P2-only methods; variable tails require the fixed
prefix. Invalid windows, lengths, capacity or produced counts refuse with `6700`;
unknown ordinary INS refuses with `6D00` after window validation.

Fixed response capacity is checked before callback entry; the callback receives
the exact declared width and must return that width. Variable callbacks receive
the offered capacity and must return `0..capacity`. Replies remain whole-only:
127 bytes at offset 6 and 13 bytes at offset 7 fit a 133-byte buffer; 190/177-byte
issuer replies require a larger caller buffer and transport capable of sending
the entire response. Insufficient capacity refuses rather than creating a stream.
Simulator capacity is not physical-card capacity qualification.

Callbacks are trusted. They can write before returning an invalid count, write
outside their authorized span, or mutate state. No sandbox, rollback or wipe is
promised. Protected helpers validate whole-array bounds; handlers must respect
their own span. Classic CAP conversion uses `ints="true"` because existing u32
fields and helpers use int arithmetic. Actual optional-int support, physical
installation, APDU capacity/transport, timing, endurance, total RAM/NVM and
consumer-owned arrays remain deployment/consumer obligations.
