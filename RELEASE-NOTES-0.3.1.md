# javacard-rpc-server-javacard v0.3.1 release candidate

This candidate adds explicit proportional cleanup for persistent stream
workspace while preserving the raw-array handler API. The planned root tag
`v0.3.1` identifies both the Go backend and Java runtime at one repository
commit. These pins become usable after publication.

## Changes and compatibility

- Set `pluginapi.Schema.Applet.StreamWorkspaceCleanup` to `whole-reply-area`
  with `StreamWorkspace` set to `persistent`. Call
  `codegen.Plugin{}.Generate(schema, options)` with the existing namespace and
  simulator dependency options. Handlers retain their raw-array signatures.
- Successful request copies track their written prefix. Before handler entry,
  cleanup marks the entire authorized reply area, covering scratch beyond the
  returned length and handler failure. Abort, deselect and successful READ
  close erase the union of the request prefix and authorized reply area.
  Untouched workspace incurs zero cleanup writes; close retries do not repeat
  the wipe. Reset retains its full workspace sweep.
- `written-bytes-only`, unknown cleanup selectors and whole cleanup with
  nonpersistent storage return errors without a partial generated package.
  The published API's written-mode constant remains a compatibility symbol.
- Empty or unspecified cleanup preserves the released generated bytes and
  file ordering across the 216 frozen Java Card parity rows. Wire format and
  the root on-card runtime source are unchanged. The backend consumes published
  `pluginapi v0.1.1` without a local replacement.

See [cleanup contract and measured costs](PERSISTENT-WORKSPACE-COSTS.md) for the
full example and real Auth comparison, exact source/tool identities, RAM, CAP
and call inventories. The selected whole mode preserves raw handlers with a
2 B transient-state increase. The rejected writer experiment required a 2048 B
staging arena; its measurements remain historical evidence and its API does
not ship. Auth observed stores cover instrumented Auth/generated primitive
array writes into owned persistent arrays, including deselect; provider-origin
output writes are outside that observer and have separately stated bounds.
The table therefore does not claim exact all-origin NVM savings.

## Validation and limits

The backend requires Go 1.25+. The root runtime uses JDK 17, Gradle 8.12,
Java 8 source/bytecode compatibility and `com.klinec:jcardsim:3.0.5.9`.
Retained native evidence covers real simulator lifecycle/refusal/reset,
allocation and narrowing controls, four default/whole CAP converter/verifier
variants, and byte identity with the measured whole Auth generated sources.
The Auth comparison uses its documented Relux jCardSim `3.0.5.9-relux.2`
identity; the generated example uses the separate `relux.1` lane.

These checks do not establish physical timing, endurance, total card NVM,
engine-private RAM, torn-write atomicity or physical-card installation.
Parsing, CLI defaults and safe file publication belong to the selected facade
or direct consumer; this target returns files in memory. Optional native tests
skip without their toolchain variables; required Make lanes reject missing
configuration. A default Go pass alone does not establish native coverage.
