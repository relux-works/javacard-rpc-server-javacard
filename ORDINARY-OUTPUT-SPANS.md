# Ordinary output spans

This prototype intentionally breaks the generated Java callback/dispatch API.
Regenerate subclasses and migrate their implementations; there is no array-return
compatibility shim. IDL, INS values, field order, big-endian scalar encodings,
Kotlin/Swift wire and stream lifecycle are preserved. Fixed ordinary requests now
require their exact declared data length (including zero for P1/P2-only methods);
a variable tail requires at least the fixed prefix.

## API

```java
public final short dispatchTo(byte ins, byte p1, byte p2,
        byte[] requestBuffer, short requestOffset, short requestLength,
        byte[] output, short outputOffset, short outputCapacity);

// Fixed/packed/variable byte-sequence response callbacks:
protected abstract short onGetAuthenticationIdentity(
        byte[] output, short outputOffset, short outputCapacity);
protected abstract short onGetAuthAppletInfo(
        byte[] output, short outputOffset, short outputCapacity);

// Each byte-sequence request field becomes three callback arguments:
protected abstract short onEcho(short prefix,
        byte[] payload, short payloadOffset, short payloadLength,
        byte[] output, short outputOffset, short outputCapacity);
```

Single u8/bool/u16/u32 responses keep byte/boolean/short/int callback returns;
no response keeps a void callback. Generated code packs scalar returns directly
into output without allocating a reply. Compound responses write their existing
encoded field order. Each borrowed byte-sequence argument references the original
request buffer; generated code no longer slices/allocates request arrays.

Generated ordinary names share a deterministic allocator seeded with every
request field name before rendering. It reserves generated parameters/locals and
borrowed Offset/Length companions as it chooses them, trying base, base_1,
base_2, etc. Occupied suffixes are skipped, including names of later fields.
This is not a new reserved IDL prefix. Callback types/order and positional
dispatch calls stay the same; generated parameter names can change when needed
to avoid a collision. Noncolliding schemas retain their exact generated bytes.

## Capacity and ownership

All offsets/lengths/capacities are nonnegative JavaCard shorts. An offset may equal
array length only for an empty span. Null output is always refused. Null request
is permitted only for `(offset=0, length=0)`; the skeleton's install-time empty
array supplies the no-data case. Window validation subtracts from array length
after checking the offset, avoiding addition overflow. Arrays and schema spans
must fit JavaCard Classic's short-indexed array model; this is not support for
host JVM arrays larger than 32767 bytes.

Fixed response capacity is checked before the callback. That callback receives
the exact declared width, even when the caller offers more room, and must return
that width. Variable callbacks receive the offered capacity and must return
`0..capacity`. Invalid windows, request lengths, insufficient fixed capacity,
negative/over-capacity/wrong-width lengths refuse with `6700`; unknown ordinary
INS refuses with `6D00` after window validation. Replies are whole-only: no
partial return, new reply array, retained output reference or constructor APDU
binding is required.

A 127-byte identity fits a 133-byte buffer at offset 6; a 13-byte applet info
reply fits at offset 7. A 190/177-byte issuer reply requires a sufficiently large
caller buffer AND a transport/platform capable of sending that whole reply.
Neither fits a minimum 133-byte APDU array, even at offset zero. The dispatcher
refuses insufficient capacity and does not turn an ordinary reply into a stream.
Do not infer physical card buffer capacity from a simulator.

APDU arrays are command-local variables/parameters only. The generated code
stores neither incoming nor output references in fields or array components.
Subclasses must follow the same ownership rule. Typed scalar request fields are
fully decoded before the callback or packing writes. Borrowed byte spans may
alias output: consume all needed input before overwriting it. `packBytes` has
memmove semantics for one overlapping span in either direction; multiple copies
can still overwrite input needed by a later copy. Use a deliberate copy order or
an appropriate caller-owned workspace, never a retained APDU binding.

Callbacks are trusted: bounds/length checks do not sandbox arbitrary handler
stores. A handler can overwrite neighbors, mutate state, or write output before
returning an invalid length. No rollback or wipe is promised. A failed dispatch
returns no sendable length, so the caller must send only after successful return.
Protected packing helpers validate whole-array bounds, not the callback's span;
handlers must also respect their capacity.

## Caller send site

```java
// Fully receive the request first; capture INS/P1/P2 before writing an overlap.
byte[] buffer = apdu.getBuffer();
short outputOffset = (short) 0;
short produced = logic.dispatchTo(ins, p1, p2,
        buffer, requestOffset, requestLength,
        buffer, outputOffset, (short) (buffer.length - outputOffset));
// This point is reached only on successful dispatch. Map StatusWordException
// to ISOException in the caller; do not send staged bytes after a refusal.
if (produced > 0) {
    apdu.setOutgoing();
    apdu.setOutgoingLength(produced);
    apdu.sendBytesLong(buffer, outputOffset, produced);
}
```

Ordinary APDU receiving/sending remains caller-owned. The existing generated
stream adapter still handles stream instructions through `dispatchStreamTo` and
has unchanged output/lifecycle bytes. Its mixed-schema fixture's ordinary send
site was migrated to use `dispatchTo`, the nonzero offset and produced length.
